## Access and retention limits

Authenticated metadata reports `draft: true`, `published_at: null`, and `immutable: false`. Anonymous requests to the release, installer asset API and installer URL returned HTTP 404. GitHub documents [draft-release access](https://docs.github.com/en/rest/releases/releases#list-releases), and the CLI's [`--draft` option](https://cli.github.com/manual/gh_release_create) leaves a release unpublished.

Draft assets remain editable or deletable by repository writers. They are not immutable. Retain these IDs and checksums, never replace these assets in place, and create a new candidate record for changed files. Any missing object or digest mismatch blocks using it for qualification. Accepted-baseline retention remains governed by the [baseline policy](../upgrade-baselines.md).

This was an authenticated command-line download on macOS 27.3 arm64. It does not establish browser quarantine, fresh-account Finder installation, minimum-supported-OS coverage, native unavailable-store behavior or complete VoiceOver acceptance. No accepted release baseline is registered, and publication remains a separate maintainer decision.

## Retrieve this exact candidate

Use authenticated GitHub CLI access with permission to read the draft. These commands retrieve the pinned asset IDs into a new temporary directory, rather than relying on a moving tag or `latest` URL. Stop if a download or checksum fails.

rowberry_candidate_dir=$(mktemp -d)
cd "$rowberry_candidate_dir"
while read -r asset_id asset_name; do
  gh api -H 'Accept: application/octet-stream' \
    "repos/adamspicedev/rowberry/releases/assets/$asset_id" > "$asset_name"
done <<'ASSETS'
